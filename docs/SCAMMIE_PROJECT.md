## 1. What Scammie Is

**Scammie** is a Blue Team cybersecurity training app. The user plays realistic chat
conversations with scammers (fake IT support, delivery scams, Telegram job scams) inside a
safe simulated messenger. Every reply they choose is scored, and at the end they get a
**Risk Report** showing how close they played to a perfect run, with feedback explaining
each mistake. Results are saved to their account so they can track improvement over time.

- **Direction:** Blue Team (defensive / awareness training)
- **Team:** 2 members
- **Deadline:** Saturday **July 26, 2026, midnight** (source code + slides; jury at CADT)

## 5. Data Design

### 5.1 The models (final — do not build against old `Scammie.md` models)

```
UserProfile   { uid, username, email, bestScore, gamesPlayed }
Scenario      { id, title, sender, category, steps: List<ChatStep> }
ChatStep      { id, botMessages: List<String>, choices: List<ChatChoice> }   // empty choices = ending
ChatChoice    { text, safePoints, riskPoints, feedback, nextStepId? }
GameResult    { id?, scenarioId, scenarioTitle, difficulty, scorePercent, safeActions, riskyActions, mistakes: List<String>, playedAt }
```

Key ideas:
- A **scenario is a scripted conversation** made of steps. Each step = scammer messages + player choices.
- `nextStepId` allows **branching**: sharing the OTP code leads to a "hacked" ending, refusing leads to a pressure step, etc.
- **Adding a scenario never touches logic** — only `default_scenarios.dart`.

### 5.2 Firestore structure (cloud)

```
users/{uid}                          ← UserProfile document
    username, email, bestScore, gamesPlayed
users/{uid}/results/{autoId}         ← one GameResult per finished run
    scenarioId, scenarioTitle, difficulty, scorePercent,
    safeActions, riskyActions, playedAt (ms since epoch, for ordering),
    mistakes (list of rule strings — lets History reopen a run's full report)
```

Security rules: a signed-in user can read/write **only their own** `users/{uid}` tree
(rules text is in `MEMBER1_GUIDE.md` §2.5).

### 5.3 Full CRUD coverage (say this on the slides)

| Op | Where in the app | Repository method |
|---|---|---|
| **C**reate | Sign Up creates the profile; finishing a game creates a result | `AuthRepository.signUp`, `ResultRepository.saveResult` |
| **R**ead | Profile screen, History screen, auth state | `getProfile`, `getHistory`, `authState` |
| **U**pdate | Best score & games played after each run; username in Edit Profile | `ResultRepository.saveResult`, `AuthRepository.updateUsername` |
| **D**elete | Swipe-to-delete a run in History (with confirmation) | `ResultRepository.deleteResult` |

### 5.4 Local data

- `default_scenarios.dart` — 3 scenarios written (IT/OTP scam, delivery-link scam,
  Telegram job scam), each with branching and feedback lines. More welcome if time.
- SharedPreferences — `hasSeenOnboarding`, `lastDifficulty`.

## 7. Game Rules

### Scoring
- Each choice adds `safePoints` (good reactions) — risky choices add `riskPoints` and count as a risky action.
- At every choice point, the **best available** safePoints value is added to a "possible" total.
- **Final score = earned safe points ÷ possible safe points × 100** → "how close to a perfect run".

### Risk level & badge (from score %)
| Score | Level | Badge |
|---|---|---|
| 80–100 | LOW | Cyber Survivor |
| 50–79 | MEDIUM | Almost Hacked |
| 0–49 | HIGH | Data Leaked |

### Difficulty
- **Easy:** choice buttons show a hint (e.g. small shield icon on safe choices), forgiving wording.
- **Hard:** no hints, identical scoring. (Per Figma: "Guided hints - forgiving scoring" / "Vague hints - no mercy in scoring".)

## 12. Jury Talking Points (for the slides)

- *"Scammie uses a data-driven scenario engine: every scam conversation is data, not code —
  adding a new scam means adding one entry to a Dart file, with zero logic changes."*
- *"We split data by purpose: game content is local so gameplay works offline; results and
  accounts are in Firestore so progress follows the user across devices."*
- *"We secured Firestore with rules so each user can only access their own data."*
- *"Every piece of information in the app passed one test: can the user act on it? That's
  why our report centers on 'what to remember' rules instead of charts, and why history
  rows reopen as lessons."*
- *"Our device feature extends the mission: the report is exported as a real file and
  shared through the system share sheet — awareness training that spreads itself."*
- Honest limitation to state proudly: scripted scenarios can't cover every scam — the app
  teaches the common patterns; future work is a Firestore scenario feed and an AI
  free-play mode (which would need a backend proxy to protect API keys).
